# 2026-08-17 — Progress Update & Next Stories

**Type:** Internal team meeting
**Attendees:** Tasmiya, Mmaphefo, Kgotlelelo, Lindokuhle, Kgethego

## Summary

Everyone gave an update on their work since the [Aug 4](./2026-08-04.md)
kickoff, then chose the next user stories to pick up.

## Updates

### Tasmiya — E1: Auth and Roles

- Set up authentication with Clerk, including coach login.
- Built the invite/roles system: a coach invites an assistant via a unique
  link; on signup, the assistant is correctly assigned `role: assistant` and
  linked to the right squad — preventing anyone from signing in and simply
  claiming to be a coach or assistant.
- Merged this into the `roster-management` branch and updated the webhook
  and Dashboard UI to match its design system and schema.
- Tested the full combined flow end-to-end: coach signup → squad
  auto-created → invite generated → assistant signup via link → correct
  role and squad assignment confirmed in Postgres.
- Fixed the CI/CD pipeline by adding an action runner — Gitea Actions now
  runs on a self-hosted Oracle Cloud VM, with frontend and backend
  connected and working.

### Mmaphefo — E3: Event Management

**US5 — Create a Match or Training Event**
- Event creation form UI.
- Training/Competition type toggle.
- Saving events to Postgres, linked to the squad.

**US6 — Edit or Cancel an Event**
- Pre-populated edit form.
- Cancel implemented as a status change, not a hard delete, to preserve
  history.

### Kgotlelelo — E2: Roster Management

- Set up the local dev environment (Docker Postgres, Clerk auth, both
  servers wired up and running).
- Designed and migrated the `squads` and `athletes` tables — a squad is
  auto-created for a coach on their first athlete add, no separate setup
  step needed.
- Built the athletes API (GET, POST, PATCH, DELETE) with ownership checks
  at the API level — a coach can only view/edit/delete athletes in their
  own squad, verified via `squad_id` lookup rather than just checking
  "logged in."
- **Found and fixed a Clerk auth bug**: `req.auth.userId` is deprecated in
  the installed `@clerk/express` version and silently returns `undefined`.
  Switched all routes to `getAuth(req)` instead.
  :::caution Follow-up needed
  Worth checking whether any other routes are still using the old
  `req.auth.userId` pattern.
  :::
- Built the full roster UI: add/edit/remove athlete flow, a roster grid
  with squad-number-forward cards, and an empty-state prompt when no
  athletes exist yet.
- Built a shared design system (white/gold/sky-blue, Real Madrid–inspired)
  and a sidebar layout shell, reskinning Home, Dashboard, and Account
  Settings, which were still on the raw Vite starter template.
  :::note Touches shared files
  Flagged for the team since this affects shared files — worth walking
  through the diff together before merging.
  :::
- Tested the full flow end-to-end: coach signup → squad auto-created → add
  athlete → edit → remove, confirmed working against local Postgres.
- Pushed to `feature/roster-management`, PR into `main` opened.

### Lindokuhle — CI/CD Pipeline

- Created the Gitea workflow (`ci.yml`) so every push and pull request is
  automatically validated: frontend lint + build, and backend lint + tests
  run against a fresh PostgreSQL instance — confirming migrations and
  business logic work correctly in a clean environment.
- Also added backend tests, `eslint.config.js`, `package.json`, and the
  corresponding `package-lock.json`.

### Kgethego — Live Event Logging & Dashboard/Stats (newly claimed)

Picking up the stories left unclaimed at the Aug 4 kickoff — core Basic
tier features:

**US13** — log a scoring moment or notable action against an athlete during
a live event, with a real-time record. *AC: select athlete + action type
(goal/point/penalty/etc.) + timestamp, saved immediately.*

**US14** — edit or undo a log entry just made, to fix in-the-moment
mistakes. *AC: each entry has edit/delete, changes reflected instantly in
the UI.*

**US15** — store each event's final result and any penalties recorded, for
a permanent record. *AC: event detail page shows aggregated result + full
timeline of logged actions.*

**US16** — a live dashboard during an event, showing the timeline of
logged actions as they happen. *AC: real-time (or near-real-time) view of
an in-progress event's log.*

**US17** — a per-athlete summary view, with stats derived from logged
events (goals, penalties, appearances). *AC: click into an athlete from
the roster to see their aggregated stats across events.*
